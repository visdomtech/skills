# Sync RAG Metadata Cache

## Overview

Synchronize the `rag_metadata_cache` collection in Firestore for a specific document after its metadata has been updated in Vertex AI via MCP tools. This ensures that future reports generated by `report_rag_metadata/generate_rag_metadata_report.py` reflect the most recent changes without requiring a full refresh from the API.

## Prerequisites

- Access to the Orca MCP server (for context and verification)
- **Firestore Access**: Google Cloud credentials configured for the `regulations` database in project `visdomapp-1`.
- `uv` for Python environment management.

### Prepare Documents Data

Before syncing, ensure the documents cache is up-to-date. If `assets/compliance_documents.json` does not exist or is stale, run:

```bash
cd orca
uv run fetch-compliance-documents --config assets/mcp_config.json
```

This script generates the required `assets/compliance_documents.json` file used to map RAG file names to document filenames.

## Workflow

### Step 1: Prepare Environment

Ensure your virtual environment is set up and dependencies are installed:

```bash
cd orca
uv sync
```

### Step 2: Identify Document Details

Before syncing, you need the **filename** associated with the RAG file and the **metadata key/value** you intend to sync. 

If you only have the `ragFileName`, use `mcp__orca__list_rag_metadata` to verify the current state, then look up the corresponding filename in `assets/compliance_documents.json`.

### Step 3: Execute the Sync Script

Use the `rag-metadata-sync-cache` script to update the Firestore cache for a single document.

```bash
uv run rag-metadata-sync-cache \
  --config assets/mcp_config.json \
  --filename "Your_Document_Name.pdf" \
  --key "jurisdiction_code" \
  --value "US-CA"
```

| Flag | Required | Description |
|---|---|---|
| `--config` | yes | Path to the MCP configuration JSON. |
| `--filename` | yes | The exact filename of the document as it appears in the compliance repository. |
| `--key` | yes | The metadata key to update (e.g., `jurisdiction_code`). |
| `--value` | yes | The new value for the metadata key. |

### Step 4: Verify Synchronization

To confirm the cache was updated, you can either:
1. Check the console output of the script for a success message.
2. Run the `rag-metadata-report` script again and observe that the document now reflects the new metadata value.

## Important Notes

1. **One Entry at a Time:** This script is designed to sync a single metadata entry for one document. For bulk updates, consider re-running the full `rag-metadata-report` script with the `--force-refresh` flag.
2. **Cache Consistency:** Always perform this sync immediately after successfully updating metadata in Vertex AI using `create_rag_metadata` or `update_rag_metadata`.
3. **Filename Accuracy:** Ensure the `--filename` matches exactly what is stored in `compliance_documents.json`. Mismatches will result in the cache not being found or updated correctly.
