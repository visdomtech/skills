# Law Changes Report

## Overview

Generate a professional, Gmail-compatible HTML report from Orca law changes data. The report includes categorized tables, jurisdiction breakdowns, action items with urgency indicators, and is optimized for email delivery.

The report is generated by `orca/scripts/generate_law_changes_report.py` which handles all analysis, categorization, and HTML generation with inline CSS.

## Prerequisites

- Access to the Orca MCP server
- The `get_latest_law_changes` tool

## Step 1: Fetch Data

Call `get_latest_law_changes` with a `sinceDate` parameter (ISO 8601 format: YYYY-MM-DD).

**Default:** If no date is provided, use 7 days ago.

**Optional filters:**
- `changeType`: "Amendment", "New Law", or "Update"
- `jurisdiction`: e.g., "US-CA", "US-NY"

### API Response Structure

The response contains a `changes` array with these fields:

```json
{
  "changes": [
    {
      "billNumber": "",
      "changeType": "Update",
      "jurisdiction": "US-WA",
      "summary": "Brief description...",
      "researchContent": "Detailed content...",
      "revisedEffectiveDate": "2027-06-30",
      "revisedEnactmentDate": "2027-06-30",
      "status": "Active",
      "trackerStem": "Labor And Employment New Laws...",
      "uploadDate": "2026-04-27"
    }
  ],
  "count": 15
}
```

**Important:** The response field is `changes`, not `lawChanges`.

## Step 2: Generate the Report

Use the automated script:

```bash
python3 orca/scripts/generate_law_changes_report.py <input_json> [output_html] [date_range_label]
```

**Parameters:**
- `input_json` (required): Path to cached response JSON or raw API response
- `output_html` (optional): Output file path. Default: `law_changes_report.html`
- `date_range_label` (optional): Date range text for report header

### Example Workflow

```bash
# 1. Fetch data via MCP tool (cache is saved automatically)
# 2. Generate report from cache
python3 orca/scripts/generate_law_changes_report.py \
  orca/cache/orca_cache_<hash>.json \
  orca/law_changes_report.html \
  "April 15 - April 28, 2026"
```

## Report Structure

The generated HTML report contains these sections:

1. **Hero Header** — Dark navy background with title, date range, and orange total-count badge
2. **Summary Cards** — Three cards showing: Amendments (orange), New Laws (red), Updates & Reg Changes (green)
3. **Jurisdiction Breakdown** — Blue-accented grid showing changes per jurisdiction
4. **Categorized Tables** — Law changes grouped by topic:
   - Non-Compete & Restrictive Covenant Changes
   - Minimum Wage & Compensation
   - Anti-Retaliation & Workplace Rights
   - OSHA & Workplace Safety
   - Notable Court Decisions
   - Federal Regulatory Proposals & Updates
   - Other Law Changes (fallback)
5. **Key Action Items for Employers** — Changes grouped into 4 themed cards with urgency-colored left borders and AI-generated natural-language narratives:
   - **Immediate** (red) — effective within 30 days; grouped by jurisdiction with specific compliance actions (e.g., "Review non-compete agreements with...")
   - **Upcoming** (orange) — effective within 31–90 days; grouped by jurisdiction with numbered multi-point action lists
   - **Ongoing** (green) — already effective items with continuing compliance significance; themed (e.g., "Heat Safety", "Compliance")
   - **Monitor** (blue) — proposals with comment deadlines and far-future items to track for planning
6. **Footer** — Data source info and DoubleFin branding

### Design Notes

- Table-based layout with inline CSS only (Gmail-compatible)
- Fixed-width inner table (700px) centered in full-width outer table
- All visual styling is handled by the Python script

## Key Points

1. **Change types:** The API returns "New Law", "Amendment", "Update" (not "NEW", "AMENDMENT", "REPEAL")
2. **Date formats:** May be YYYY-MM-DD (date only) or ISO 8601 datetime. The script handles both.
3. **Categorization:** Based on `trackerStem` + `summary` + `researchContent` keyword matching
4. **Priority logic** (for analysis summary; action items use separate bucket logic below):
   - High: `changeType` = "New Law" OR effective within 30 days
   - Medium: effective within 31–90 days OR `changeType` in ("Amendment", "Update") without effective date
   - Low: already effective or no effective date
5. **Action item bucket logic** (groups all changes into 4 thematic cards):
   - Immediate: 0–30 days until effective
   - Upcoming: 31–90 days until effective
   - Ongoing: already effective (days < 0)
   - Monitor: no effective date or >90 days out
   - Within each bucket, items are grouped by jurisdiction + theme; narratives are synthesized from summaries, bill numbers, wage amounts, and comment deadlines
6. Cache responses per Orca caching policy (24-hour expiration)
